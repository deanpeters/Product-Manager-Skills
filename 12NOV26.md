### 1. Guided Context Capture (the facilitation contract)

**What it is:** the named, user-facing contract for how every interactive skill gathers context and hands the decision back. Dean considers it a differentiator across his repos.

- **Rules live in one place:** `skills/workshop-facilitation/SKILL.md`. Other skills *link* to it. **Do not copy the protocol text into skills.** (The source version of this idea used word-for-word copies with a checker. That was rejected here because it breaks the no-tight-coupling rule.)
- **Explainer:** `docs/guided-context-capture.md` (why it exists, the seven moves, a worked context-dump read, how it differs, how to set the default). Linked from the README right after the "Why no `$ARGUMENTS`" note.
- **Five behaviors added to the rulebook:**
  1. Context dump shows its read first: **Known / Assumed / Missing / Conflicting**, keeping what a source *reported* apart from what is *verified*
  2. Options sharpen each turn. Search grounding is optional (only if the runtime has search); never invent specifics
  3. **Completion summary** (supplied · inferred · unknown or disputed · ready?) and confirmation before generating the artifact
  4. **Decision ladder:** `(Recommended)` first, two or three distinct alternatives with one-line tradeoffs, then `Other`
  5. **Ranked** Assumptions to Validate; "go back to Qx" replays with updated options; resume opens with a recap
- **New named pitfalls:** The Silent Resolve, The Flat Assumption List, Generating Before the Recap, Placeholder Options, The Stalled Opening.
- **Contradiction sweep result:** six scripted openings listed the three modes and then *waited* for a pick. All now open in the default mode in the same turn. `ai-shaped-readiness-advisor`'s local context-dump and assumptions rules were brought in line.
- **Known, not contradictions:** `tam-sam-som-calculator`, `incoming-request-advisor`, and `eol-process` produce Assumptions to Validate lists that don't say "ranked." They lag the rulebook but don't contradict it. Optional polish.

### 2. Configurable default entry mode

- **Master setting:** `pm-skills.config.yaml` (repo root). `facilitation.default_entry_mode` is one of `guided | context-dump | best-guess`, plus `overrides` by skill folder name. Ships as `guided`, with one override: `incoming-request-advisor: context-dump` (its pasted message *is* the context; this matches its prior behavior).
- **Per-skill line:** 33 skills (the rulebook + 32 that run the protocol) carry exactly one line beginning `**Default entry mode:** Guided · …`. It exists so a skill installed alone (a single Claude Desktop ZIP, which does **not** include `workshop-facilitation`) still knows its default and what each mode does.
- **Precedence:** user's in-session choice › config file (if the agent can read it) › the skill's line › Guided. The default only sets the first turn; all three modes are always offered. This honors the standing rule that **intensity is a dial the user sets.**
- **Script:** `scripts/apply-entry-mode.py`
  - no args: rewrite `skills/` from the config
  - `--check`: exit 1 on drift, unknown mode values, overrides naming unknown skills, or **a skill that says "use [`workshop-facilitation`]" above its References but lacks the line** (this closes the gap for new skills)
  - `--skills-dir DIR --filename Skill.md`: stamp a packaged copy
- **Wiring:** `package-claude-skills.sh` and `build-codex-skills.sh` stamp their packaged copies; `--check` runs in `validate-skills.sh` (the CI path) and step 4 of `test-library.sh`. Unlike `check-dist-freshness.py`, it is safe inside `validate-skills.sh` because its fix is the script itself, not a rebuild.
- **Not included on purpose:** `autonomous-investigation` (sibling protocol, doesn't run this one), `stakeholder-engagement-advisor` and `stakeholder-mapping` (mention the protocol only in References).
- **Authoring guidance updated:** CONTRIBUTING interactive checklist, `pm-skill-creator` draft step, `skill-authoring-workflow` Phase 3.

## How this session's source material worked (repeatable pattern)

Both new docs arrived as **untracked files written for a different, private repo** (they referenced its scripts, folders, and naming). The pattern Dean approved:

1. Read it fully and identify what's foreign (paths, scripts, product names, private URLs).
2. Map each foreign piece to this repo's real counterpart, or drop it.
3. Add what *this* repo would add (ABC, the no-coupling rule, the `$ARGUMENTS` stance, fictional universes).
4. Sweep the result for leftover foreign names before committing.
5. Never commit the original as-is.

## Standing conventions (do not regress)

1. **ABC: Always Be Coaching.** Explanation is load-bearing; stripping teaching to tighten copy is a defect.
2. **Intensity and mode are dials the user sets.** Recommend, honor the override, name what the lighter choice leaves uncovered. Never default to the heaviest level.
3. **No tight coupling between skills.** Link to a source of truth; no copied protocol blocks, no handoff schemas. Per-skill lines (like `Default entry mode`) are small, self-describing, and machine-checked.
4. **Provenance:** cite public, linkable work by name; for unpublished or client material, cite the practice, not the artifact. Never commit a denylist. No customer names or recognizable engagements; use the fictional universes (Fieldlight, Northfield Automation, Brightwater Biologics, scoped).
5. **Commercial neutrality:** no vendor links or vendor-dependent skills (see CONTRIBUTING).
6. **No `$ARGUMENTS`** in skill bodies; plain-language `## Input` sections.
7. **Commit only when asked; tag only when told "tag."** Dean pushes directly to `main`; branch protection only blocks force-push and deletion.
8. `check-dist-freshness.py` stays **outside** `validate-skills.sh` (self-abort loop). `apply-entry-mode.py --check` stays **inside** it.
